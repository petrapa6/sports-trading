# T05 verification — Home Assistant app packaging

Environment: GitHub Actions `ubuntu-24.04` runners (Docker Engine with Compose and Buildx, QEMU via
`docker/setup-qemu-action`), Node.js v22.23.2, 2026-09-26. Image base
`ghcr.io/home-assistant/base:3.22-2026.08.0@sha256:0eda502b…` (Alpine 3.22, `nodejs` 22.23.2-r0).

**Why the container checks ran in CI, not in the development session:** the development container's egress
policy lets Docker fetch GHCR manifests but refuses the blob host (`pkg-containers.githubusercontent.com`) and
the Alpine package CDN, so the Home Assistant base image cannot be pulled or `apk add` run there. Everything that
needs the image therefore runs in `.github/workflows/image.yml`, which executes the same `npm run verify:T05` a
developer runs locally. Items that do not need the image (check:addon, config diff, DOCS/translations) were also
run in the session and passed there. The fd-3 hand-over was additionally rehearsed on the host (Node 22.22.2):
`bash -c "exec node dist/server/main.js --kalshi-private-key-fd=3 3< <(base64 -d …)"` → no fd 3,
`environ` grep 0, `/api/dev/key-fingerprint` = `openssl pkey -pubout | sha256sum`.

Automated checks: `cd kalshi-trader/app && npm run verify:T05` (items 1–5, 7–9) and
`npm run verify:T05 -- --only=arm64` (item 6). They use `<repo>/.local/verify-T05/` and the Compose project
`kst-verify-t05` on host port 8199, generate a throwaway RSA key with `openssl genpkey` (keys are never committed),
turn a fixture `config.local.json` into a root-owned `options.json` with `npm run compose:options`, and let
`run.sh` hand the key over on fd 3 exactly as on Home Assistant.

Green run: <https://github.com/petrapa6/sports-trading/actions/runs/36206993925> (Image, commit `e82ffb1`: jobs
*amd64 image — compose, run.sh, key hand-over* and *arm64 + amd64 build (QEMU)*), together with CI run
<https://github.com/petrapa6/sports-trading/actions/runs/36206993944> (lint, typecheck, test, e2e, audit, gitleaks).

### Notes

1. The literal `sh -c 'stat -c %u /proc/$(pgrep -f dist/server/main.js)'` printed `1000` followed by
   `stat: can't stat '94'`: busybox `pgrep -f` also matches the `sh -c` running the command (its own command line
   contains the pattern), which has exited by the time `stat` runs. The only Node process (`pgrep -x node`) runs as
   uid 1000; that is what the script asserts.
2. `docker compose exec` runs as root **without** `CAP_SYS_PTRACE`, and the kernel refuses root reading
   `/proc/<pid>/environ` or fd link targets of a uid-1000 process (`Permission denied`, which silently turns the grep
   count into `0`). The script therefore reads them as uid 1000 and first asserts that `environ` is readable and
   non-empty. An earlier run also showed that a keep-alive HTTP client from the host keeps a socket in the app
   (which the kernel numbers 3 once the key fd is closed); the host checks use `curl` (one request per connection).
