## Observations

- better-sqlite3 is synchronous, so the 5 s `busy_timeout` wait blocks the event loop and requests queue behind
  it. That is why a 10 s lock produces one `db_busy` answer, not one per request. The drill records this; nothing
  was changed.
- While Kalshi is down, each tick waits for the Kalshi feed's backoff (0.5 + 1 + 2 + 4 s), so ticks come about
  every 12.5 s instead of every 5 s. The NHL state never got older than `maxFeedAgeSec` (15 s).
- Found by the drill and fixed: with msw, the Kalshi client's `await res.body.cancel()` on a 5xx never settled,
  which hung the request. The cancel is no longer awaited.
