# T03 verification — Request classes, authentication, sessions, HTTP hardening, audit log

Environment: Linux x86_64 (running as root), Node.js v22.22.2, npm 10.9.7, Fastify 5.12.5, @fastify/helmet 13.1.1,
@fastify/rate-limit 11.2.0, @fastify/cookie 11.1.2, @fastify/csrf-protection 8.0.1, argon2 0.45.1, otplib 13.5.0,
2026-09-25.

Automated checks: `cd kalshi-trader/app && npm run verify:T03`. Each item runs its Vitest file(s) in
`test/security/` and, where the check can be made over real HTTP, repeats it against `npm run dev`
(`TRUSTED_PROXIES=127.0.0.1/32`, so a loopback request with `CF-Connecting-IP` is class `tunnel`, one without
it class `dev`). Peers that cannot be produced from localhost (the ingress proxy `172.30.32.2`, `172.30.33.5`,
`10.0.0.9`) are covered with `app.inject({ remoteAddress })`. Time-dependent items fake `Date` only
(`vi.useFakeTimers({ toFake: ['Date'] })`), which also drives the rate limiter's window.

### Item 10 by hand (restart with and without `secret.key`)

```bash
export DATA_DIR=./.local/manual/data DB_PATH=./.local/manual/trader.db
npm run dev &                                              # generates .local/manual/data/secret.key
curl -s -c jar -X POST localhost:8099/setup -H 'content-type: application/json' \
  -d '{"username":"pavel","password":"a very long password"}'   # {"ok":true,"username":"pavel"}
stat -c %a .local/manual/data/secret.key                   # 600
curl -s -b jar -o /dev/null -w '%{http_code}' localhost:8099/auth/me   # 200
# restart with the same key                                → 200
# stop, rm .local/manual/data/secret.key, start again      → 401 {"error":"unauthorized"}
```

The third start logs `Generated a new secret.key; existing sessions and encrypted settings are invalid` (info),
deletes the stale `sessions` rows (0 left) and writes `secret_key_generated` to `audit_log`.
